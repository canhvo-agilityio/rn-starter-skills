rn-starter Skills

From a machine with nothing installed to a running React Native app, then screens built from your design, by talking to Claude. Claude installs the environment, asks you to pick the stack, scaffolds the project to the team's standard, runs the app on the targets you chose, and checks every screen against the design.

macOS · Windows · Linux Expo SDK 58React Native 0.88 Expo or RN CLI
Two skills

One job each, connected through the project

rn-starter

Clean machine → running app

You say: "Create a new React Native app"
You get: a standard project and the app running

  • Checks the machine and installs what's missing: Node, JDK 17, Android SDK + emulator, Xcode / iOS Simulator, CocoaPods
  • Asks step by step; every question has a recommended answer
  • Scaffolds a layered structure (screens, components, hooks, services) with tests, git hooks, commit rules and Claude Code files
  • Runs the app on every target you picked before handing over
rn-design-import

Design → working screens

You say: "Build the app from this Figma" / "Add the Checkout screen from this screenshot"
You get: screens, theme, fonts, navigation

  • Takes a description, screenshots or a Figma link
  • Writes design-spec.md for you to approve before any code is generated
  • Works on new projects and existing apps
  • Opens every screen, screenshots it and compares it with the design

The skills are independent: rn-starter can stop at an empty app, and rn-design-import runs on any RN/Expo project. They connect through .rn-starter.json, which records every stack choice, so generated screens always use the project's libraries and conventions.

Code quality (defaults)

  • Before commit: ESLint auto-fix, Prettier, tests related to the changed files
  • Before push: type check, all unit tests
  • Commit messages: Conventional Commits, or your team's own rule
  • ESLint rules: UI gets data only through hooks (never services or mocks); shared code never imports screens

Checked before hand-over

  • tsc, ESLint and unit tests pass
  • Hooks block a bad commit and accept a good one
  • The first screen is visible on every selected target
  • Anything approximated is listed under Open points

Claude Code in the project

  • CLAUDE.md: stack, commands, structure and code-style rules
  • A hook formats and lint-fixes every file Claude edits, and sends leftover errors back to Claude
  • A code-reviewer subagent reviews your changes before you commit

Theme and icons

  • Tokens from the design; light/dark only if the design has both, otherwise locked to the design
  • Plain StyleSheet, NativeWind, Unistyles or React Native Paper, each set up its own way
  • Icons are SVG components you can size and tint with theme colors

The skill spots these in the design and suggests a library for your framework: Expo and RN CLI get different choices. Before suggesting one, it checks live whether the library is maintained, supports the New Architecture and runs in Expo Go. You choose the real library or a placeholder, and it tells you up front what's needed (API key, permissions, a native rebuild).

Your part

What Claude can't do for you

At these steps Claude stops, gives you the exact commands, and keeps working on anything that doesn't depend on them.

  • Download Xcode from the App Store (a free Apple ID is enough)
  • Commands that need a password: sudo xcodebuild -license accept on macOS; turning on Windows Hypervisor Platform and restarting on Windows
  • Accept the Android SDK license
  • Scan the QR code with Expo Go on your phone and confirm you see the app
  • Approve the stack choices and design-spec.md
Get started

Install the plugin and try it

1. Install Claude Code (no Node needed), then the plugin:

claude plugin marketplace add canhvo-agilityio/rn-starter-skills#dev
claude plugin install rn-starter@rn-starter-skills

2. Open a new session in an empty folder and just ask:

  • Create a new React Native app
  • Create an RN app with 5 screens: Login, Home, Search, Detail, Profile
  • Create an RN app from this Figma design: <link to a frame>
  • Add a Checkout screen from this screenshot (in an existing project)

Why it works this way

Design principles

Clear blockers, stop only for people
A missing tool is the wizard's job, not homework for the developer.
Never offer what can't work
Questions are filtered by your machine and by your earlier answers.
Verify by looking
Done means a screenshot of the running app, not a successful build log.
Live facts over fixed lists
Versions, maintenance status and New Architecture support are checked at run time.
Follow the project
It extends the existing theme and components and doesn't restructure your code unasked.
The model decides, scripts execute
Reasoning stays with Claude; installs and checks are scripts that behave the same on every machine.

Limits and roadmap

What it doesn't do yet, and what's next

Out of scope

  • Store builds and releases, code signing
  • Business logic and real API integration (screens use mock data)
  • Pixel-perfect copies; the aim is close to the design, on tokens
  • Native builds on a physical iPhone (use Expo Go instead)

Planned skills

  • rn-api-connect (next): switch services/ from mocks to real APIs, from OpenAPI, Postman or docs
  • rn-auth: real sign-in, secure tokens, protected routes
  • rn-forms: react-hook-form + zod, shared field components
  • rn-e2e: Maestro tests for the main flows
  • rn-release: EAS builds and store releases
  • Later: rn-i18n, rn-upgrade, rn-observability, rn-ci
